# 001 — переход витрины на @moysklad/uikit 31.20.0: контекст

## Зачем

Витрина и выгрузка в Claude Design собраны на `@moysklad/uikit` 28.1.0 (май 2026). В npm вышли 30.4.0 (30 июня) и 31.20.0 (4 сентября). Дизайн-агент в Claude Design видит старый набор: нет 12 новых компонентов, у 23 существующих устарел API, нет новых токенов. Цель — витрина на 31.20.0, покрывающая новый публичный API, и обновлённая выгрузка в Claude Design.

## Что известно до старта (разведка 2026-10-12)

Разведка шла на копии репозитория во временной папке: пакет 31.20.0 установлен, витрина собрана. Рабочую копию разведка не трогала.

- **Сборка почти цела.** `npx tsc --noEmit` на 31.20.0 даёт одну ошибку: у `Help` убран проп `icon` (`src/stories/catalog/Help.stories.tsx:19`). `storybook build` проходит. Рантайм не проверялся — это первая неизвестная плана: `tsc` и сборка рантайм-падений не ловят (см. HANDOFF, «Верификация»).
- **Ничего из использованного витриной не удалено.** `FieldRow`, `Info`, `InputClear` переехали в `dist/components/_shared/`, но подпути `@moysklad/uikit/components/<Name>` в `exports` остались и ведут к существующим файлам.
- **Главный вход больше не реэкспортирует `hooks`, `icon`, `utils`.** Витрина берёт иконки из `@moysklad/uikit/icon`, а `useSnackbar` и `useFileUploader` по-прежнему в главном входе — поэтому `tsc` чист. Учитывать при новых историях: иконки только через `/icon`.
- **Новые публичные компоненты (12).** В главном входе: `BentoBlock`, `EditableDate`, `Informer`, `Layout`, `LabelValueCheckbox`, `LabelValueFile`, `LabelValueLink`, `StatusBadge`, `ViewersStack`. Только через подпуть: `DateRange`, `Panel`, `FieldLabel`. `DateRange` крупный (около 1000 строк типов, свои типы значений и хелперы периодов) и интерактивный.
- **Изменён API у 23 существующих компонентов** (по числу изменённых строк в `.d.ts`): Textfield, Multiselect, Select, Chip, LabelValue, Help, Breadcrumbs, Link, Input, Tooltip, EditableTitle, InputUnit, Button, LabelValueSelect, AutoComplete, Dropdown, Datepicker, MentionsTextfield, LabelValueInput, FileUploader, EmptyState, Checkbox, Label. Плюс `data-grid` — около 370 изменённых строк. Часть изменений — внутренняя перестройка типов, часть — новые пропы и значения (например `Help` получил `HelpSize`, `Multiselect` — `AllSelectedChipTextVariant`), часть — новые пометки `@deprecated` (Chip, Checkbox, AutoComplete). Что из этого видно пользователю, выясняет задача разведки в этапе 1, а не исполнители поодиночке.
- **Токены.** Удалён `--elements-disabled` (его перечисляет `src/stories/tokens/Colors.stories.tsx`). Добавлены `--light-blue-50`, `--bgd-accent`, `--border-focused` и два новых слоя: `gwt-status` (16 цветов статусов `--gwt-statuses-*`) и `viewers-stack` (`--viewers-stack-*`).
- **Иконки.** 306 → 318 (новые семейства `MsLogo`, `MyApps`, `Phone`, `Smile`, по три размера). Галерея `tokens/Icons.stories.tsx` динамическая — правка не нужна, только цифры в документах.
- **Зависимости пакета.** Ушли `lodash.debounce` и `lodash.isequal`; `@tanstack/react-table` в пакете по-прежнему точно `8.21.3` — совпадает с витриной, фиксация остаётся.
- **В пакете нет CHANGELOG.** Изменения восстанавливаются только сравнением `.d.ts` старой и новой версии.

## Почему такой порядок

1. **Сначала переход и разведка, потом правки.** Без рантайм-прогона и сводки изменений API исполнители историй будут каждый заново сравнивать `.d.ts` и угадывать, что показывать. Сводка делается один раз и служит общим входом и критерием.
2. **Существующие истории раньше новых.** Существующие уже выгружены в Claude Design, их поломка — регресс. Новые — прирост.
3. **Новые компоненты параллельно.** Каждая история — отдельный файл, задачи не пересекаются. Общие файлы (`extra-exports.ts`, `Introduction.mdx`, документы) вынесены в отдельные задачи, чтобы не править один файл параллельно.
4. **Выгрузка в Claude Design — последней и вне оркестрации.** Она идёт через инструмент `DesignSync` и навык `/design-sync`, требует решения владельца по проекту и визуальной сверки в браузере под его учёткой. Оркестратор останавливается перед ней.

## Решения по объёму (приняты автором плана, владелец может пересмотреть)

- **Сразу на 31.20.0**, промежуточная 30.4.0 пропускается: она ничего не даёт витрине, а сравнение всё равно делается с конечной версией.
- **Зависимость — `^31.20.0`**, как было с `^28.1.0`; в lock-файле — ровно 31.20.0.
- **Истории показывают новые видимые варианты** (новые значения enum-пропов, размеры, режимы), но не каждое внутреннее изменение типов.
- **Истории не используют пропы с `@deprecated`.** Если существующая история их использует — переводится на канонический проп.
- **`Info` и `Informer` — оба остаются**, если `Info` не помечен `@deprecated`. Помечен — `Info` убирается из витрины и выгрузки, как раньше `Switch`.
- **DataGrid-демо не расширяется.** Только чинится, если сломано: расширенное демо — отдельная будущая задача из HANDOFF.
- **Рантайм-проверка — скриптом в репозитории**, а не ручным прогоном в браузере. В HANDOFF описан ручной метод через скрытый iframe; здесь он превращается в скрипт на `playwright-core` (devDependency). На машине есть `/usr/bin/google-chrome` и браузеры Playwright в `~/.cache/ms-playwright`. Так критерий «история рендерится без ошибки» становится машинным и повторимым для верификатора.

## Решения, которые ждут владельца

Ни одно не блокирует этапы 1–4. Все нужны до этапа 5.

1. **Куда выгружать в Claude Design.** Рекомендация — в текущий проект `60c8aa90-acf4-42c8-a017-03288eda7056`: он создан через API (`create_project`), закреплён в `config.json` и уже работает в режиме галереи. Правило NOTES «всегда создавать через `create_project`» запрещает переиспользовать проект, созданный в интерфейсе, — к этому проекту оно не относится. Новый проект — только если владелец хочет сохранить старую выгрузку нетронутой для сравнения.
2. **Галочка Published** в проекте Claude Design. Сейчас снята. Включить — дизайн-система станет доступна новым проектам команды.
3. **Коммиты и push.** Коммит после принятой волны — по слову владельца при старте прогона. Push в `main` запускает деплой витрины на GitHub Pages (`.github/workflows/deploy.yml`) — только по прямой просьбе.
4. **Старый проект `b8937eea-acb1-4ab3-aa64-9e7e589c2d9d`** в Claude Design помечен на удаление, удаляется только вручную в интерфейсе. Удалён ли — неизвестно.

## Что отклонено

- **Переход по одной мажорной версии за раз** — двойная работа без пользы для витрины.
- **Оставить 28.1.0 и выгрузку как есть** — дизайн-агент проектирует на устаревшем наборе компонентов.
- **Ручной рантайм-прогон через браузер агента как критерий** — не повторим верификатором без участия человека и плохо ложится в волновую приёмку.

## Ловушки, о которых должны знать исполнители

- Документы репозитория местами устарели: CLAUDE.md и NOTES.md говорят «не git-репозиторий», а это git-репозиторий. Источник истины по состоянию — сам репозиторий.
- API читать только из `node_modules/@moysklad/uikit/dist` после этапа 1, не по памяти и не по документам. Пропсы часто в `<Name>.types.d.ts`. Имена иконок сверять по `dist/icon/components/`.
- Группа в `title` истории — латиницей (`Компоненты/<Group>/<Name>`), иначе конвертер выгрузки кладёт компонент в `misc`. Существующие группы: Actions, Containers, Fields, Forms, Navigation, Overlays, Status, Typography.
- Компоненты только из подпути должны быть реэкспортированы в `.design-sync/extra-exports.ts`, иначе конвертер их не видит.
- Почти всё controlled — истории на `useState`. Оформление через `src/shared/Showcase.tsx`.
- Временные папки разведки в `/tmp` удалены, исполнители на них не опираются.
